# 设计说明（DESIGN）

## 1. 定位

cn-law-verify 是给 AI 的**法条核验层**：让任何 Agent 在引用中国法律法规
条文时做到三件事——**查得到**（从官方源取回原文）、**验得真**（代码层
逐条核验，不靠模型自觉）、**带效力与出处**（每条引用附效力状态与官方
链接）。

它补的正是现有方案共同的缺口：检索型工具只负责「取回原文供引用」，
没有「拿一段已生成的引文逐条比对、不合格就明确报错」的核验环节；
而大模型法条幻觉里最危险的一类恰恰是引用了不存在、已废止或
张冠李戴的条文。

## 2. 形态：MCP 为体、Skill 为矩

- **MCP server（体）**：提供检索与核验的原子工具，核验逻辑是确定性
  代码（存在性／逐字比对／效力三检），不经模型。stdio＋Streamable HTTP
  双传输，保证本地型与托管型 Agent 都能接。
- **SKILL.md（矩）**：配套规矩层，规定「先查后引、引用必带效力与
  出处、查不到明说、发现废止点名排除、工具不可用时不许无核验输出」。
- 两者分工：工具给能力，Skill 给编排，宿主产品的管线给强制
  （例如在回复发出前强制过一遍整段核验）。

## 3. 经验继承：站在 flk-mcp 的肩膀上

本项目受朋友分享的开源项目 flk-mcp 启发，为独立重写实现。
以下做法经其实践验证有效，直接继承：

| # | 继承的经验 | 在本项目中的落点 |
|---|---|---|
| 1 | 三库按法规层级分工选库（法律/地方性法规/司法解释→国家法律法规数据库；行政法规→司法部国家行政法规库；部门规章＋地方政府规章→国家规章库） | P0 先落 flk 一库；857（0.3.0）三库全部接通：flk_search 三库合并检索、verify/get_law/get_article 在 flk 未收录时转 moj 条级核验、再转 gzk 存在性。实测限制如实记录：moj 检索端点当前不按关键词过滤——857 时兜底只对返回页内精确命中生效；859（0.4.0）实测同一端点的 PageIndex 分页有效，遂离线遍历全库建成标题索引（data/moj_index.json，1,189 行含同名历史版本／官方现行有效口径 603 部），标题检索与精确兜底改走索引、覆盖全库，效力与原文仍走详情页实时取数；moj 详情页无效力字段（恒标未核或据列表页标注）、gzk 无官方效力字段与全文（结论封顶 exists_only） |
| 2 | 效力状态强制呈现（官方 `sxx` 字段映射为有效/已修改/已废止/尚未生效） | 每条工具出参强制带 `status`/`status_code` |
| 3 | 同名多版本优先现行有效版 | `find_law` 的版本选取顺序：有效 > 已修改 > 尚未生效 > 已废止 |
| 4 | 条号归一化（阿拉伯↔中文数字互转、按条号定位截取） | `normalize_article`/`extract_article`，核验比对的地基 |
| 5 | 官方链接溯源 | 每条结果带 `source_url` 指向官方详情页 |
| 6 | 两段式输出（机器结论与人工复核分开说） | 核验结果结构化呈现 checks 与 verdict，人工复核清单在 P2 的 `lookup` 工具落地 |
| 7 | 白名单＋HTTPS 纪律（请求只发官方域名） | `_check_url` 全量校验，无例外路径 |
| 8 | 遇验证码/拦截页立即终止，不硬闯官方站 | 响应含验证页特征即报错终止 |
| 9 | 单次查询不落盘、不缓存（实时通道纪律） | server 无任何文件写入；发往官方源的只有本次检索词 |
| 10 | SKILL.md 异常处置话术（点名问题法规、解决前排除、不可用时给替代渠道） | SKILL.md 第三、四节 |
| 11 | 零依赖单文件交付（clone 即可跑） | P0 纯标准库单文件 server |
| 12 | 下载解析防护（DOCX 体积/条目上限） | 下载 50MB、解压条目 5000、解压总量 100MB 上限 |

## 4. 缺点与解法：flk-mcp 没做完的，我们补上

| # | 原缺点 | 本项目的解法 | 状态 |
|---|---|---|---|
| 1 | 无代码层核验拦截：「强制核验」靠宿主 AI 自觉遵守 Skill | 新增 `verify_citation`（单条三检）与 `check_citations_in_text`（整段抽取逐条比对） | 已落地 |
| 2 | DOCX 下载关闭 TLS 证书校验、重定向目标不复检 | 全程默认证书校验；重定向逐跳复检域名（白名单＋对象存储域名后缀清单）；响应体按 Content-Length 验完整，DOCX 下载支持 Range 断点续传 | 已落地 |
| 3 | 逆向接口易碎（官网改版/加验证码即失效） | 双通道：快照库通道＋实时复核通道；结论恒标注通道与时间，绝不静默冒充 | 已落地（快照首批覆盖见 README） |
| 4 | 宣称的测试未随包附带 | 测试与评测集随仓交付：单测＋联网集成用例（真法条/编造法名/条号漂移/废止旧条文）；评测集 200 题（eval/），只公布方法与题集，不喊未经复核的准确率 | 已落地 |
| 5 | 个别可配置 URL 能绕过白名单 | 目标域名不可配置：环境变量只许调超时，任何 URL 在启用前过同一白名单函数 | 已落地 |
| 6 | 关键词查询只有上下文窗口、长条文截断 | 全文通道按条返回完整原文；窗口兜底时出参标注 `text_source=official_context_window` 并降级结论 | 已落地 |
| 7 | 规章库无官方效力字段、层级靠推断 | 推断字段一律标 `inferred: true` 并注明依据；效力无法确认时写「效力未核」 | 已落地（857 随 gzk 通道）：gzk 结果 status 恒为「效力未核」、verify 结论封顶 exists_only、不提供条文原文 |
| 8 | 只解决「取真原文」，不解决「引得对不对」（引注真实但不支持论点） | 存在性＋逐字＋效力三检做满；蕴含核验 `check_support` 做诚实的词面启发式初筛（四档结论），工具描述与每次输出明示「不能替代人工判断」，不包装成确定性判定 | 已落地；857 升 v2：信号从三类扩到七类（新增排他性限定、条件偷换、单位偷换、主体偷换），44 题人工金标集（tests/support_gold.jsonl）命中 20/44 → 44/44；859 升 v3：新增数量边界方向信号并修掉 v2 的过拟合面（条件弱标记降级、款项序号污染、主体宾语误绑等），三套集实测——金标 44/44 不退步、新构造对抗集 30/32、独立保留集 41/60 → 50/60（余下分歧多为「核心真实＋附加编造」题的评级口径差异，如实记录）；860 升 v3.1：新增分档锚定信号（多档条文按情形锚定分句再比方向），对抗集 30/32 → 31/32，余 1 题（论断整段丢弃一档情形）经终审裁决为词面方法结构性盲区、不上语义路线，盲区写入 README 与 SKILL.md 明示使用者；2026-11-26 升 v4.0（0.5.3）：严格口径重做——逐分句核对门、数字所指对调信号、极性许可肯定 guard；三套开发集金标 44/44、对抗 32/32、新建 v4 开发集 23/24（余 1 题为成对主体表外的主体偷换，记为已知边界；正式复评须全新密封集＋用户点头） |

## 5. 工具面（8 个，全只读）

| 工具 | 说明 | 状态 |
|---|---|---|
| `flk_search` | 三库官方源实时检索法规（source=auto/flk/moj/gzk，带效力状态、官方链接与所属库标记） | ✅ |
| `verify_citation` | 单条引注三检：存在性／效力／原文逐字比对 | ✅ |
| `get_law` | 单部法规元数据＋目录大纲＋版本沿革（官方详情页） | ✅ |
| `get_article` | 单条条文逐字原文（快照优先、实时兜底） | ✅ |
| `search_articles` | 跨法规条文级检索（快照为主、实时兜底并注明覆盖） | ✅ |
| `check_citations_in_text` | 整段文本引注抽取＋逐条核验 | ✅ |
| `lookup` | 一句话直达，两段式输出 | ✅ |
| `check_support` | 蕴含初筛（词面启发式，明示非语义判定） | ✅ |

全部工具标注 `readOnlyHint: true`；出参恒带 `data_snapshot`
（通道、来源、取数时间；快照通道另带数据截止日）。

## 6. 数据源策略

- **实时通道（P0 已落地）**：国家法律法规数据库 flk.npc.gov.cn 官方
  前端接口（官方无公开 API，此为公开事实）。检索走 `search/list`，
  全文走官方 DOCX 下载（`download/mobile?format=docx`），逐字比对
  以 DOCX 全文整条截取为准；DOCX 不可用时降级为 `hitDisplay`
  上下文窗口并在出参中如实标注、降级结论。
- **快照通道（已落地首批）**：`tools/build_snapshot.py` 以 flk 官方
  DOCX 离线建条级 SQLite 快照库（串行限速、断点续传、覆盖清单入库），
  首批收录核心法典与高频法律（清单见 README）；857 起按枚举清单
  （`tools/enumerate_flk.py`，国家层面现行有效 1,837 部）全量扩建，
  `tools/update_snapshot.py` 负责增量保鲜（元数据比对、变化才重建、
  新法限量并入）。快照结论恒带构建时间，不冒充实时。
- **兜底通道（857）**：flk 未收录的法规依次转 moj（详情页全文条级
  三检）、gzk（仅存在性）；目标域名仍只许白名单四域名，网关地址
  与公开应用标识写死常量、不许环境变量改写。
- **降级口径**：实时复核不可用时，返回结论必须标注所依据的快照
  截止日；两种通道的结论永不混写。

## 7. 通用性

- 传输：stdio（本地型客户端全员支持）＋ Streamable HTTP（已落地，
  `--http` 启动；ChatGPT 网页版等只收远程 HTTPS server 的场景）。
  不提供已废弃的 HTTP+SSE。
- 协议：按 2025-03-26／2025-11-25 会话式语义实现、兼容 2024-11-05，
  请求处理保持无状态，为后续无状态规范留升级口。
- 配置：只走环境变量且只许调超时一类参数，目标域名不可配。
- 版本：server 语义化版本与数据版本分离，出参结构带 `schema` 字段。

## 9. 安全边界

- server 只读、无写工具、无用户凭据概念；本地 stdio 模式下，
  待核验文本不出本机（`verify_citation` 只向上游发法名与条号）。
- 托管模式下文本会到达 server 运营方，使用者应知情选择——
  README 中有明示。
- 法规文本源自国家法律法规数据库公开数据；代码以 MIT 许可证发布。
